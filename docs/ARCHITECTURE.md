# System Architecture

## Self-Hosted Single-Tenant Design
This platform is intentionally designed as a self-hosted, single-tenant application (not a multi-tenant SaaS). This ensures true data isolation.

## Core Entities
- **User**: The base account model. Uses role-based access control (RBAC).
- **Roles**:
  - `admin`: Has full instance-level control. Identical permissions to Organizer, plus access to instance-wide audit logs and role management.
  - `organizer`: Creates and configures events, provisions judge accounts via one-time invite links, oversees teams and submissions, and exports results. Organizers cannot self-signup; the first one is created via a one-time Setup Wizard.
  - `judge`: Can only view assigned submissions and submit scoring rubrics. Provisioned via invite links generated by organizers.
  - `participant`: Creates teams, submits projects, and views public galleries. Can self-signup.
- **Event**: Represents a hackathon. Contains tracks and prizes.
- **Team**: Participants group into teams to create a submission.
- **Submission**: The project submitted by a team.
- **JudgeAssignment**: Links a judge to a submission.
- **Score**: The grading provided by a judge for a specific submission.

## Stack Choices
- **Backend:** Node.js + Express + TypeScript
- **Frontend:** React + Vite
- **Database:** PostgreSQL via Prisma
- **Deployment:** Docker Compose

## Request Flow
Client -> Frontend (React) -> Backend API (Express) -> PostgreSQL (Prisma)
